# Новини для нового сайту futsal.com.ua — передача від команди CRM АФУ

Відповідь на afu-crm#1. Стан на 27.09.2026. Усе, що описано, вже живе в Xano і в CRM
(afu-crm `d1acf53`, `9ba5d46`).

## Головна відмінність від запиту: сайт читає не через Metadata API, а через окрему групу `site`

У запиті пропонувалось читати таблиці через токен Metadata API. Ми цього **не радимо і не
підтримуємо**: цей токен відкриває весь воркспейс, включно з таблицею користувачів і поштами
вболівальників. Замість нього створено публічну групу **лише на читання, без авторизації**:

```
https://xdeg-kg7i-jjtu.f2.xano.io/api:tqrLXZWT
```

Вона віддає лише опубліковані новини з датою публікації, що вже настала, і лише активні рубрики.
Чернетки, відкладені й архівні новини та новини у вимкнених рубриках через неї недоступні
(404). Ніякого токена на сайті зберігати не треба.

## Ендпоінти групи `site`

### `GET /news` — стрічка

| Параметр | Тип | Типово | Що робить |
|---|---|---|---|
| `page` | int | 1 | сторінка |
| `per_page` або `limit` | int | 20 | розмір сторінки, стеля 50 (обидва імені рівнозначні) |
| `since` | int, мс | 0 | лише новини з `published_at` пізніше за це значення (для «оновити») |
| `category` | text | — | `slug` рубрики |
| `tournament_id` | int | 0 | новини, прив'язані до турніру сезону (`Leagues.id`) |
| `club_id` | int | 0 | новини, прив'язані до клубу (`TeamInfo.id`) |
| `match_id` | int | 0 | новини, прив'язані до матчу (`Match.id`) |
| `featured` | bool | false | лише «на головній» |

Відповідь:

```json
{ "items": [ …картки… ], "total": 0, "page": 1, "per_page": 20, "totalPages": 1 }
```

Картка (`items[]`): `id`, `title`, `slug`, `lead`, `cover` (url), `cover_thumb` (url, ≤ 400 px,
для карток), `cover_alt`, `category` (`{id, name, slug, competition_id}` або `null`),
`is_featured`, `video_url` (або `null`), `tournament_ids[]`, `club_ids[]`, `match_id` (або
`null`), `published_at`, `updated_at`. Сортування — від новішої до старішої.

### `GET /news/{slug}` — сторінка новини

Те саме, що картка, плюс `body_html` (готовий HTML, очищений на сервері) і `gallery`
(`[{image, alt, caption}]`). Чернетка, відкладена, архівна, у вимкненій рубриці або
неіснуюча адреса → **HTTP 404** з `{"code":"ERROR_CODE_NOT_FOUND","message":"Новину не знайдено"}`.

### `GET /news-categories` — рубрики

Масив `{id, name, slug, competition_id, sort_order}`, лише активні, у порядку `sort_order`, потім
за назвою. Зараз порожній: рубрики заводить адміністратор у CRM.

## Що варто знати сайту

- **Дати — epoch у мілісекундах** (`published_at`, `updated_at`), не ISO.
- **Рубрика одна** (`category`), не масив.
- Адреса сторінки збирається з `slug`: `/novyny/{slug}/`, як у запиті; slug унікальний.
- `body_html` містить h2–h4, жирний, курсив, посилання, списки, цитати, зображення з
  `width`/`height`, таблиці, вбудований YouTube. Текст чиститься двічі (DOMPurify у CRM і на
  сервері), але сайт має рендерити його як довірений HTML лише з цього джерела.
- Обкладинку для карток беріть з `cover_thumb`, для сторінки — з `cover`.
- Зв'язки з турнірами, клубами й матчем — це `id` з наявних таблиць `Leagues`, `TeamInfo`,
  `Match`, які сайт уже читає.
- Наявні групи `Default`, `crm`, `authentication` не змінювались. ADMIN і фан-застосунок
  працюють як раніше; фан-застосунок поки читає новини зі старого сайту і перейде на цю групу
  після переїзду сайту.
- Групу можна кешувати на CDN: відповіді не залежать від користувача.

## Що в CRM (для редакторів)

Розділ «Новини»: список із пошуком і фільтрами, форма з редактором (заголовок, адреса з
заголовка за транслітерацією КМУ 2010, анонс, текст, обкладинка з описом і мініатюрою, галерея,
YouTube, рубрика, зв'язки з турнірами/клубами/матчем, «на головній», відкладена публікація),
кнопки «Зберегти чернетку» і «Опублікувати» (перевіряє обов'язкові поля), видалення лише
чернеток. Розділ «Рубрики». Право «Редагування новин» є в ролі «Адмін».

## Чекліст готовності з запиту

- [x] У Xano є таблиці `news` і `news_category` з полями запиту (плюс `cover_thumb`, `status`, `is_featured`).
- [x] У CRM можна створити, відредагувати й опублікувати новину з обкладинкою.
- [x] Чернетки і новини з майбутньою датою не видно через `site`, опубліковані — видно (перевірено живцем: порожній список 200, неіснуючий slug 404).
- [x] Наявні екрани CRM, ADMIN і фан-застосунок працюють як раніше (чинні групи API не змінювались).

Питання — у afu-crm#1.

## Доповнення 27.09: жива перевірка в CRM і чотири виправлення

Перевірено під логіном адміністратора (звіт `docs/reports/crm.md` у afu-futzal). Що спрацювало:

- відмови сервера: погана адреса → 400; дубль адреси → 400; неіснуюча новина → 404;
  «Опублікувати» без обов'язкових полів → 400 зі списком, чого бракує; обхід через
  `PATCH status=published` → 400 (публікація лише через `POST news/{id}/publish`);
- сервер чистить текст: прибирає `onclick`, `style`, `script` і чужі `iframe`; `javascript:`
  у посиланнях стає `#`; вбудований YouTube лишається;
- обкладинка й мініатюра завантажуються; `img` та `iframe` зберігаються з `width` і `height`;
- через `site`: чернетка не видна (`/news` → `total: 0`, `/news/{slug}` чернетки → 404).

Виправлено під час перевірки (afu-crm `35fac17`):

1. перевірка адреси відхиляла й правильні slug — перенесено в лямбду;
2. `PATCH` без адреси падав — порожній рядок тепер означає «не передано»;
3. `POST news/images` не віддавав `url` — тепер добудовується з `path`;
4. очищення HTML викидало `width`/`height` у зображень — виправлено, дозволені схеми
   посилань лише `https`, `mailto`, `tel`.

**Ще не перевірено:** успішна публікація, бо рубрик у базі поки немає, їх заводить адміністратор.
Перша опублікована новина з'явиться в `GET /news` одразу після публікації в CRM.

У базі зараз одна тестова чернетка (`test-perevirka-crm`), через `site` вона недоступна;
адміністратор її видалить.
