Рішення Андрія 29.09: беремо три роботи в такому порядку. Виконує сесія **CRM Xano**
(`local_90acf602-bee7-4c11-8e31-9d6cd6c50d28`), приймає PM 1 живими запитами до групи `site`.

Спільні правила для всіх трьох:

- **Тільки додаємо.** Групи `Default` (`api:DSaYr0P-`), `crm`, `authentication` і чинні таблиці не
  змінюються — ними живуть застосунок, ADMIN у Draftbit і сама CRM. Усе нове — у групі **`site`**
  (`api:tqrLXZWT`, без авторизації, лише читання) і в нових таблицях.
- Кожна нова таблиця й кожне поле в чинній — **лише зі словом Андрія**: спершу знімок схеми і
  перелік, потім його «так». Повний PUT схеми — лише зі словом PM (валідатори trim уже раз злітали).
- Перед правками в Xano — резервна копія (Ігор просить у кожному issue; робить Андрій або ти з його
  дозволу).
- Логіку ендпоінтів — через Metadata API як `text/x-xanoscript`, чернетки в
  `afu-futzal/docs/xano/drafts/`, як для новин. Токен у Keychain.
- Зразок для CRM-екранів і прав — розділ «Новини» (`NewsPage.jsx`, `NewsEditPage.jsx`,
  `NewsCategoriesPage.jsx`, право 13 у ролі «Адмін»). Для кожного нового розділу — окреме право.
- Коміти в `afu-crm` явними шляхами; після кожної частини — короткий лист PM 1: коміт, ендпоінти,
  один живий приклад відповіді. Відповідь Ігорю в issue пише PM 1.
- Документ для сайту: `docs/peredacha-web-sport-api.md` (частина 1), а частини 2 і 3 — дописати в
  `docs/peredacha-web-novyny.md`-подібні файли `docs/peredacha-web-partnery.md` і
  `docs/peredacha-web-dokumenty.md`. Формат — як у передачі новин: адреса групи, параметри, поля,
  коди помилок.

## Частина 1 (перша). Безпечні спортивні дані в групі `site` — закриває afu-crm#3 і пропозицію з #1

### Навіщо
Живими запитами 29.09 підтверджено: `Default` без авторизації віддає для 686 людей і 104 суддів
повну дату народження й по батькові, а `match/{id}` — прізвище делегата (`delegat`,
`users_idDelegat`), спостерігача (`Sposterigach_ar`), хронометриста (`timekeeper`) і
`other_comments`. Прибрати це з `Default` зараз не можна (застосунок: екрани гравця, судді, матчу;
ADMIN: вісім екранів і рапорт PDF; CRM). Тому сайт отримує **власний набір читальних ендпоінтів
без особистих полів**, після чого відкликає токен Metadata API (Ігор погодився в #1). Закриття
`Default` — окремий крок, разом із 23 незахищеними операціями запису (`docs/backlog.md`).

### Що віддати (усе `GET`, без авторизації, лише «опубліковане/активне»)

| Ендпоінт | Джерело | Поля у відповіді | Чого НЕ віддавати |
|---|---|---|---|
| `/seasons` | `Season` | id, name, start_date, end_date, is_current | — |
| `/leagues?season_id=` | `Leagues` + `league` | id, name, short_name, logo (url, width, height), kind (ліга/кубок), type (нац./міжн.), season_id, show_in_app, stages[] (id, name, sort), tours[] (id, number, name, date_from, date_to) | внутрішні прапорці |
| `/leagues/{id}/participants` | `Tournament participants` | teaminfo_id, group_name, withdrawn, club {id, name, logo} | — |
| `/leagues/{id}/zones` | зони таблиці | id, name, color, place_from, place_to | — |
| `/leagues/{id}/table` | як `table` у Default | те саме, що в застосунку | — |
| `/matches?league_id=&tour_id=&date_from=&date_to=&club_id=` | `Match` | id, TimeOfMatch, league_id, tour_id, stage, match_number, teams {id, name, short, logo}, result, fouls по половинах, status, venue {id, name, city}, referees[] (id, first_name, last_name — троє), is_top, video_id, spectators, breaks (4 хв.) | делегат, спостерігач, хронометрист, `other_comments`, `users_idDelegat` |
| `/matches/{id}` | те саме одним записом | + events[] (Statistic: minute, type_id, type_name, player, team, assist), lineups[] (Team + Zaiuavka: player, number, position, is_captain), staff[] (заявка штабу) | те саме |
| `/clubs` і `/clubs/{id}` | `TeamInfo` | id, name, short_name, logo (url, w, h), team_kind, country, Relevance, parent_teaminfo_id, home_venue {id, name, city}, city, founded, colors | контакти клубу, email, телефони, юридичні дані |
| `/clubs/{id}/squad?league_id=` | `Team` | player {id, first_name, last_name, photo (url, w, h), birth_year, city}, number, position, Captain, Date, End_date, Relevance_of_the_record | дата народження, по батькові |
| `/clubs/{id}/staff` | `Administration of teams` | person {id, first_name, last_name, photo}, position, date_from, date_to — одним списком з історією | контакти |
| `/people/{id}` | `People` | id, first_name, last_name, photo (url, w, h), birth_year, city, Growth, Weight, career[] (клуб, ліга, сезон, номер) | `Date_of_birth`, `po_batkovi`, паспорт, адреса, телефон |
| `/judges` і `/judges/{id}` | `judges` | id, first_name, last_name, photo (url, w, h), birth_year, city, Relevance | дата народження, по батькові |
| `/venues` і `/venues/{id}` | `Venues` | id, name, city, address, capacity, photo | — |
| `/event-types` | довідник подій `Statistic` | id, name, code | — |
| `/staff-cards?match_id=` | картки штабу | масово по матчу | — |

Дати народження — лише **рік** (`birth_year`). Фото й логотипи — об'єкт `{url, width, height}`
(Xano віддає `meta.width/height` у полі image). Неіснуюче або приховане → HTTP 404 з
`{"code":"ERROR_CODE_NOT_FOUND","message":"…"}`, як у новинах. Пагінація списків — `page`,
`per_page` (стеля 100), відповідь `{items, total, page, per_page, totalPages}`.

Якщо якогось поля в таблицях **немає** (наприклад `city` у `People`, `start_date` у `Season`) —
не вигадувати і не додавати мовчки: перелік «бракує» надіслати PM 1, Андрій вирішить.
