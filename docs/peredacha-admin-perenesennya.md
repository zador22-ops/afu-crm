# Перенести матч «Онлайн» чи «Зіграний» — контракт сервера

Від CRM (команда 2), 19.10.2026. Бриф PM 2 `match-postpone-after-start.md` (репо AFU), слово Андрія
19.10. Для CRM і ADMIN 2.0 (Admin АФУ). Логіка — `xano/crm/matches-id-postpone.post.xs`.

## `POST crm/matches/{match_id}/postpone`

Група `crm` (`api:6HPZ3cxp`), заголовок `Authorization` як для решти `crm`.

```json
{ "reason": "Аварійне відключення світла в залі" }
```

| Поле | Тип | |
|---|---|---|
| `reason` | text | обовʼязкове, після обрізання пробілів ≥ 3 символи |

Що робить:

1. Статус матчу → 2 «Перенесений».
2. Дописує в `Match.other_comments` новим рядком, старий коментар лишається:
   `Перенесено 19.10.2026 18:05 (був «Онлайн»): <причина>` (дата й час за Києвом).
   **Без персональних даних у причині**: `other_comments` віддає публічна група Default.
3. `CRM table recalc`: рядки турнірної таблиці цього матчу видаляються.
4. Один пуш `match_postponed` тим, хто стежить за матчем чи командами: «⏰ Матч перенесено · нову дату
   повідомимо» (шаблон `match_postponed_nodate`, бо час матчу вже минув; «тепер …» лише для часу попереду).
   Нову дату вболівальники отримають пушем «Змінено час», коли її поставлять у розкладі.
   «Кінець матчу» не йде. Збій розсилки відповідь не ламає.
5. **Події протоколу (`Statistic`), картки штабу, заявку, фоли й перерви не чіпає.** Рахунок у полях
   матчу лишається таким, як з подій (застосунок уболівальника не має показувати рахунок статусу 2,
   бриф п. 5).

Відповідь 200:

```json
{ "match": { "...": "рядок Match після зміни" }, "table": { "goals1": 2, "goals2": 1, "in_table": false, "...": "" } }
```

Помилки (`message` — текст для людини, показувати як є):

| Код | Коли |
|---|---|
| 401 | немає або прострочений токен |
| 403 | «Доступ заборонено» — немає права 2 (те саме, що для `…/result`: делегат і адмін) |
| 404 | «Матч не знайдено» |
| 400 | «Матч уже перенесений» — повторне натискання чи інший пристрій встиг першим |
| 400 | «Тут переноситься лише матч «Онлайн» або «Зіграний». Запланований — у картці розкладу» |
| 400 | «Вкажіть причину перенесення (щонайменше 3 символи)» |

Повтор безпечний: другий запит не змінить нічого й поверне 400 «Матч уже перенесений». Для ADMIN 2.0
це означає «вже зроблено», а не збій. Двох пушів від подвійного натискання не буде, лише якщо обидва
запити не прийшли одночасно, тому кнопку на час запиту вимикати.

## Що змінилось поруч

- `PATCH crm/matches/{match_id}`: статус онлайн чи зіграного матчу більше не міняється взагалі
  (раніше сервер дозволяв поставити 1 чи 2 без причини). Відповідь 400 «Матч уже онлайн чи зіграний:
  перенести його можна кнопкою «Перенести матч» на сторінці матчу». Решту полів зіграного матчу правити,
  як і раніше, можна. CRM статус такого матчу не надсилала й не надсилає; ADMIN 2.0 PATCH не використовує.
- Текст помилки статусів 3/4 у PATCH: «Результат і статус — на сторінці матчу…» замість «…в ADMIN».

## Зворотний шлях (без змін)

«Перенесений» → нова дата й статус 1 у картці розкладу (`PATCH`), «Онлайн» — з протоколу
(`POST …/result`, `match_status_id: 3`). Рядки таблиці повертаються з перерахунком і рахуються зі
збережених подій.

Статистика гравців (бомбардири, картки) перенесення не враховує взагалі: події рахуються за будь-якого
статусу матчу (слово Андрія 19.10).

Текст попередження в CRM і ADMIN 2.0 (однаковий): «Матч зникне з турнірної таблиці. Події протоколу
залишаться, але в таблицю не йдуть, доки матч не зіграють.»

- Функція «Push v2 match status»: для статусу 2 з минулим часом — шаблон `match_postponed_nodate`
  (рядок у `push_templates` додає `xano/push-template-postponed-nodate.mjs`, його видно й можна вимкнути
  на сторінці «Пуші»). Так само тепер і з запланованим матчем, перенесеним без нової дати.
