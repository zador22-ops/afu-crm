# Перенести чи призупинити матч — контракт сервера

Від CRM (команда 2), 19.10.2026. Брифи PM 2 `match-postpone-after-start.md` і `match-pause-and-note.md`
(репо AFU), слово Андрія 19.10. Для CRM і ADMIN 2.0 (Admin АФУ). Логіка — `xano/crm/matches-id-*.xs`.

**Стан: чернетка, НЕ задеплоєно.** Статус 5 і поле `Match.status_note` додає Backend (п. 1 брифа паузи);
до того ендпоінти, що пишуть `status_note`, на живому сервері не запрацюють.

Група `crm` (`api:6HPZ3cxp`), заголовок `Authorization` як для решти `crm`. Право 2 (делегат і адмін),
те саме, що для `…/result`. Помилки — `{ message }`, текст для людини, показувати як є.

## Статуси й переходи

| Звідки → куди | Як | Причина |
|---|---|---|
| 3 Онлайн → 5 Призупинено | `POST …/pause` | обовʼязкова |
| 5 → 3 «Відновити матч» | `POST …/result {match_status_id: 3}` | — (стирається) |
| 5 → 4 «Завершити» | `POST …/result {match_status_id: 4}` | — (стирається) |
| 3 / 4 / 5 → 2 Перенесений | `POST …/postpone` | обовʼязкова |
| 1 → 2 (картка розкладу CRM) | `PATCH …/{id} {match_status_id: 2, reason}` | обовʼязкова |
| 2 → 1 (нова дата) | `PATCH …/{id} {match_status_id: 1, TimeOfMatch}` | — (стирається) |
| 1 / 2 → 3, 3 → 4 | `POST …/result` | — (стирається) |
| 3 / 4 / 5 → 1 | **ніде** (400) | |

Причина (`reason`, text): після обрізання пробілів ≥ 3 символи. Іде в **`Match.status_note`** (її бачать
уболівальники, поки статус 2 чи 5) і новим рядком у `other_comments` з датою за Києвом:
`Призупинено 19.10.2026 18:05: Повітряна тривога`, `Перенесено 19.10.2026 18:40 (був «Призупинено»): …`.
Старий коментар не губиться. **Без персональних даних** — обидва поля публічні.

Таблиця: 5 — як «Онлайн» (рядки є, рахунок на момент паузи); 2 — рядків немає. Події протоколу не
видаляє жоден перехід. Статистику гравців не чіпає жоден перехід (слово Андрія 19.10).

## `POST crm/matches/{match_id}/pause`

```json
{ "reason": "Повітряна тривога" }
```

Статус → 5, `status_note` = причина, коментар, `CRM table recalc`, пуш `match_paused`
(«⏸ Матч призупинено · Повітряна тривога») — тим, хто стежить за командами чи матчем, і темі «Наживо», як
«Матч почався». Пауз за матч може бути кілька: пуш щоразу.

Відповідь 200: `{ match, table }`. Помилки: 401; 403 «Доступ заборонено»; 404 «Матч не знайдено»;
400 «Матч уже призупинено» (повтор — для ADMIN «вже зроблено»); 400 «Призупинити можна лише матч
«Онлайн»»; 400 «Вкажіть причину призупинення (щонайменше 3 символи)».

## `POST crm/matches/{match_id}/postpone`

```json
{ "reason": "Аварійне відключення світла в залі" }
```

Лише зі статусів 3, 4, 5. Статус → 2, `status_note` = причина, коментар, `CRM table recalc` (рядки
таблиці видаляються), один пуш `match_postponed`: «⏰ Матч перенесено · нову дату повідомимо» (шаблон
`match_postponed_nodate`, бо час матчу вже минув; «тепер …» лише для часу попереду). Нову дату
вболівальники отримають пушем «Змінено час», коли її поставлять у розкладі. «Кінець матчу» не йде.
Заявку, фоли, перерви й рахунок не чіпає.

Відповідь 200: `{ match, table }`. Помилки: 401; 403; 404; 400 «Матч уже перенесений»; 400 «Тут
переноситься лише матч «Онлайн», «Призупинено» або «Зіграний». Запланований — у картці розкладу»;
400 «Вкажіть причину перенесення (щонайменше 3 символи)».

## `POST crm/matches/{match_id}/result` — що змінилось

- `match_status_id: 5` — лише якщо матч уже призупинений (зберегти фоли чи коментар, не відновлюючи).
  Інакше 400 «Призупинити матч можна кнопкою «Призупинити»: там вказується причина».
- З 5 у 3 — пуш `match_resumed` («▶️ Матч відновлено · 2:1»), а не «Матч почався». З 5 у 4 — звичайне
  «Кінець матчу».
- 3 чи 4 стирає `status_note`.

## `PATCH crm/matches/{match_id}` (картка розкладу CRM) — що змінилось

- Статус онлайн, призупиненого чи зіграного матчу не міняється взагалі: 400 «Матч уже онлайн,
  призупинений чи зіграний: перенести його можна кнопкою «Перенести матч» на сторінці матчу». Решту полів
  правити, як і раніше, можна. ADMIN 2.0 PATCH не використовує.
- Новий необовʼязковий `reason`: обовʼязковий при переході в 2 з іншого статусу (400 «Вкажіть причину
  перенесення (щонайменше 3 символи): її побачать уболівальники»). Повернення в 1 стирає `status_note`.
- Текст помилки статусів 3/4 у PATCH: «Результат і статус — на сторінці матчу…» замість «…в ADMIN».

Повтор безпечний: другий запит pause/postpone нічого не змінить і поверне 400 «уже…». Кнопку на час
запиту вимикати, щоб не було двох пушів від одночасних запитів.

## Пуші й шаблони

Нові рядки `push_templates` (додає `xano/push-templates-add.mjs`, видно й можна вимкнути в «Пушах»):
`match_paused`, `match_resumed`, `match_postponed_nodate`. Нова змінна шаблонів матчу **`{reason}`** —
`status_note` (у CRM і на сервері, `push-templates-id.patch.xs`).

Тексти попереджень у CRM і ADMIN 2.0 (однакові):
- перенесення: «Матч зникне з турнірної таблиці. Події протоколу залишаться, але в таблицю не йдуть,
  доки матч не зіграють.»
- пауза: «Матч лишиться в турнірній таблиці з рахунком на момент паузи. Далі — «Відновити матч»,
  «Зіграний» або «Перенести матч».»

## Розгортання (лише після приймання PM 2 і підтвердження Андрія)

Після Backend п. 1 (статус 5, `status_note`):
`node xano/deploy.mjs` по одному з фільтрами `matches-id-pause`, `matches-id-postpone`, `matches-id-result`,
`matches-id.patch`, `push-templates-id.patch`; `node xano/deploy-fn.mjs` з `match-status`, `match-context`,
`audience`; потім `node xano/push-templates-add.mjs`. Ширших фільтрів не брати: Xano переформатовує код, і
`--check` показує «змінені» файли, яких ніхто не чіпав.
